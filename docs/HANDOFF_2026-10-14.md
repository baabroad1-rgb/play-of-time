## 1. В проекте ТРИ продукта, а не два

Это главное, что изменилось с конца сентября, и чего не знали прежние
записки.

| Что | Где | Как выкладывается |
|---|---|---|
| **Play of Time** — нативное Android-приложение, основная версия | `android/` | `build-apk.yml` → хостинг + GitHub Releases |
| **Play of Time** — веб-версия того же | `webapp/` | `deploy-web.yml` → корень playoftime.online |
| **Measurement** — отдельная игра без квестов | `measurement/` | `deploy-measurement.yml` → playoftime.online/measurement/ |

**Measurement** появился 7 октября. Это не режим внутри игры, а отдельное
приложение на своём адресе: уровень выбирается в настройках, замер
фиксированной длины (33 попытки), свой лидерборд с именами вида
`Player NNN`, свой упрощённый Analytics (попадания, hit rate, попыток на
победу, темп, геометрические средние), свой полноэкранный режим и манифест
для добавления на домашний экран. Правки шли почти ежедневно по 7–14
октября, всё описано в `docs/CHANGELOG.md`.

Своего `CLAUDE.md` у `measurement/` пока нет (у `android/` и `webapp/`
есть). Если работаешь там — правила смотри в `webapp/CLAUDE.md`, они по
духу те же, но про Measurement в них ничего.

Проверено 14.10 (`check-migration.yml`):

| версия | платформа | игроков | за неделю |
|---|---|---|---|
| не сообщ. | native | 25 | **2** |

| 15.20 | native | 2 | 2 |
| 15.10 | native | 1 | 0 |

| 14.93 | native | 1 | 0 |

Условие конца прежнее: в группах 14.9x и «не сообщ.» не осталось игроков,
заходивших за последнюю неделю. Сейчас таких трое — против десяти две
недели назад. То есть почти пришли, но ещё нет.

Единственный игрок на 14.93 последний раз синхронизировался 3 октября.

**Что сделать, когда закончится:** убрать мостовую из `downloads/`,
перенести туда новое приложение, вернуть `latest_apk.php` в
`core/update/UpdateApi.kt`, поменять `dest_dir` по умолчанию в
`build-apk.yml`.

## 4. Автоматика GitHub

| Файл | Когда | Что делает |
|---|---|---|
| `deploy-web.yml` | правки `webapp/` в main (кроме `.md`) | заливает сайт по FTPS в корень |
| `deploy-measurement.yml` | правки `measurement/` в main | заливает в `/measurement/` |
| `build-apk.yml` | правки `android/` в main (кроме `.md`) | собирает APK, кладёт на хостинг, заводит релиз, бампает версию |
| `check-build.yml` | пуш в любую ветку кроме main | только компилирует |
| `commit-log.yml` | любое изменение в main | пересобирает `docs/COMMIT_LOG.md` |
| `fix-db-config.yml` | вручную | собирает `api/config.php` на сервере из секретов |
| `check-api.yml` | вручную | опрашивает эндпоинты, сверяет выложенный `report.html` с репозиторием побайтно, печатает, какой APK по какому адресу |
| `check-migration.yml` | вручную | разбивка игроков по версиям, активность за неделю |
| `check-lucky.yml` | вручную | разовая диагностика Lucky Index |

Секреты и три классические грабли — в `HANDOFF_2026-09-26.md`, там точно.

**Правки `.md` сборку и выкладку НЕ запускают** (отрицающие пути в
триггерах, с 29.09). До этого правка одного `android/CLAUDE.md` собирала и
выкладывала игрокам новую версию без единого изменения кода.

**Два workflow могут пушить в main одновременно.** Оба обёрнуты в цикл
«пуш → не вышло → `pull --rebase` → ещё раз». Добавляешь третий пишущий —
делай так же.

**Из контейнера сессии сайт не виден** — прокси режет `playoftime.online`.
Проверка «что реально на сервере» — только запуском `check-api.yml`.
