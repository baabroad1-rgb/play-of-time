### 19 сентября (D39) — эта сессия, нативка + сервер
1. **Сортировка таблицы лидеров.** Причины: сортировка была только серверной и только по убыванию; колонка **Luck** показывала `luckyIndex`, а сервер сортировал её по `combinedScore` (уровень·1000+квест·100+SC) — поэтому «хер пойми как упорядочена». Теперь клиент один раз берёт список и сортирует **по тому числу, что показано в колонке** (`sortedBestFirst`, ничья → уровень → квест → монеты → playerId). Тап по новой колонке = лучшие сверху (▼); повторный тап по активной = обратный порядок (▲) и снова ▼. «Клювик» Алекса = стрелка в заголовке. Номер в первой колонке = **реальное место** в этом рейтинге (в обратном порядке идёт N…1).
2. **Лимит игроков сервера** `array_slice(…,100)` → `1000`, чтобы клиентская сортировка видела всех (Алекс: «ок»).
3. **Монетка SC в заголовке** — строго по центру колонки, стрелка сортировки отдельным слоем у правого края.
4. **Окно сравнения игроков:** добавлены строки **Attempts** и **Started** («N d ago»), переключатель **«All history | Same level (N)»** — виден только если игроки на разных уровнях; N = меньший уровень; в этом режиме у **обоих** берётся статистика только за этот уровень (попытки, монеты, hit rate, попыток на победу, Lucky, дата старта этого уровня). Сервер (`leaderboard.php`) теперь отдаёт `firstAttemptAt` и `tiers{1..3}` (сгруппировано по `accuracy` = уровень игры; текущая эпоха). Залито и проверено.
5. **Веб (Cowork, 19.09):** в фильтр периода Analytics веба добавлен **Week** между Day и Month (скользящее окно 7 суток) — паритет с нативным `PeriodFilter.WEEK`.

Версии нативки: 13.82 (11.09) → 13.83–13.88 (15.09) → **13.88** сортировка → **13.89** монетка+лимит → **13.90** сравнение. (В заголовке записи 19.09 в `CLAUDE.md` стоит «v13.87 → v13.88» — реально до v13.90; это ошибка заголовка, не кода.)

## 9. Как работать с Алексом (обязательные правила)

* Пишет по-русски, резко и коротко; любит **конкретные** ответы. Не заставлять его «запоминать инструкции» — давать точные шаги (какой файл, куда).
* **Отвечать явно на каждый вопрос**, даже риторический.
* Правки — **по одной**, подтверждать построчно; визуальные правки сначала **эскиз (реальный HTML, не картинка)**, потом код. Слова «кодь / поехали / делай» = хватит эскизов.
* Внешний вид — понимать **буквально** («строго по центру», «выравняй по 0»): не «примерно там».
* Терминология в тексте для игрока — игровая (precision, focus, threes, cluster), без «window / attempt limit / tolerance / IN_N».
* Числа ≥1000 в интерфейсе — с пробелом: `10 770`.
* Баги важнее фич: увидел неверную формулу — сначала чинить её.
* Команды, которые отдаёте Алексу, — PowerShell-совместимые (не `&&`).
* Не утверждать «залито», не проверив `curl`; не писать «проверено», если не запускали на устройстве.
* В конце рабочего дня — запись «What Was Done» в оба `CLAUDE.md` и (если касается отчёта) в журнал решений.
* Ничего не публиковать наружу (Artifact, сайт) без явной просьбы; секреты (`api/config.php`, `keystore.jks`) не открывать и не копировать в тексты.
