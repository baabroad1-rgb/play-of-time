# Передача: что настроено 26 сентября 2026

Короткая записка для следующей сессии. Паролей здесь нет и быть не должно —
только то, что иначе придётся выяснять заново.

## Состояние

Проект переехал в git. `main` — рабочая версия. Ветка
`claude/github-version-pjf0vs` содержит переименование пакета и перенос
истории, в `main` на момент записки **не влито**.

Читать в таком порядке: `README.md` в корне (что где лежит),
`android/CLAUDE.md` (правила проекта), `docs/CHANGELOG.md` (почему сделано
так). Что именно менялось — `git log`, там подробные описания.

## Автоматика GitHub

| Файл | Когда срабатывает | Что делает |
|---|---|---|
| `.github/workflows/deploy-web.yml` | правки в `webapp/` попали в main | заливает сайт на хостинг по FTPS |
| `.github/workflows/build-apk.yml` | правки в `android/` попали в main | собирает APK, кладёт на хостинг в `downloads/`, заводит релиз |
| `.github/workflows/check-build.yml` | пуш в любую ветку кроме main | только компилирует, никуда не выкладывает |
| `.github/workflows/commit-log.yml` | любое изменение попало в main | пересобирает `docs/COMMIT_LOG.md` из истории git |

Секреты репозитория и что в них:

* `FTP_HOST` — адрес FTP-сервера Beget
* `LOGIN` — FTP-пользователь `infousil_github`, его домашняя папка это уже
  `/playoftime.online/public_html`, поэтому в workflow пути начинаются с `/`
* `PASSWORD` — его пароль
* `DEBUG_KEYSTORE_B64` — отладочный ключ подписи с ноутбука Алекса в base64
* `DB_HOST` / `DB_NAME` / `DB_USER` / `DB_PASS` — доступ к базе лидерборда.
  На Бегете имя пользователя совпадает с именем базы: `infousil_pot`, хост
  `localhost`. Из них `.github/workflows/fix-db-config.yml` собирает
  `api/config.php` на сервере

Имена `LOGIN` и `PASSWORD` неочевидные — их задал Алекс, переименовывать без
нужды не стоит, workflow на них завязаны.

## Три грабли, на которые уже наступили

**Не называйте секрет `PATH`.** Он перекрывает системную переменную, и на
машине сборки перестаёт находиться вообще всё, включая `mkdir` и `bash`.
Ошибка при этом выглядит как отсутствие случайной утилиты и на секреты
никак не указывает. Стоило часа.

**Отладочный ключ подписи задан явно** в `signingConfigs.debug`
(`android/app/build.gradle.kts`). Без этого Android-плагин ищет ключ в
`$ANDROID_SDK_HOME/.android`, на машинах GitHub не находит и молча создаёт
новый. APK получается подписан чужой подписью и не встаёт поверх
установленного: «App not installed as package conflicts with an existing
package». Обе сборки печатают отпечаток готового APK в лог — сверяйте там,
а не на телефоне.

**Выкладка сайта затирает настройки на сервере.** 26 сентября первая же
выкладка `webapp/` залила `api/config.php` из репозитория — там вместо
пароля к базе стоит заглушка. Лидерборд лёг и на сайте, и в приложении,
всё отдавало 500. Рабочей копии на сервере не оказалось: в папке
резервных копий лежали только `.htaccess`, `_lib.php`, `set_name.php` и
`sync.php`. Пароль пришлось задать заново в панели Бегета.
Теперь `api/config.php`, `api/.htaccess` и корневой `.htaccess` исключены
из выкладки, а сам файл собирается из секретов через
`fix-db-config.yml`. **Перед добавлением чего-либо в выкладку проверяйте,
не настраивается ли это на сервере.**

**Статус сборки через API GitHub отстаёт**, иногда на минуты. Сборка может
быть давно готова, а `list_workflow_jobs` ещё показывать `in_progress`.
Не гоняйте опрос по кругу — проверяйте по результату (появился ли релиз)
или откройте страницу запуска.

## Переезд на новый идентификатор пакета

Идентификатор меняется с `ru.iflex.timemvp.quest` на `online.playoftime`.
Для Android это другое приложение: ставится рядом, база пустая.

Порядок, согласованный с Алексом:

1. Версия `14.16` старого приложения отдаёт свою историю через
   ContentProvider. **Уже в main.**
2. На сайт выкладывается новое приложение. Кнопка обновления в старом
   приложении скачивает то, что лежит по ссылке, и поставит новое рядом —
   доработка старого не нужна.
3. Новое при запуске переносит историю. Пробует при каждом запуске, пока не
   получится: игрок может поставить новое раньше, чем обновит старое.
4. Игрок убедился, что данные на месте, и удалил старое.

Известная дыра: кто не обновил старое до 14.16 и поставил новое, останется
без источника — скачать 14.16 с сайта уже не получится. Решили принять:
игроков сайдлоада пренебрежимо мало.

## Отдача данных стороннему приложению

Дневник психологического состояния читает историю через тот же провайдер.
Инструкция для их команды — `docs/CONTENT_PROVIDER_CONTRACT.md`, она
описывает то, что работает, а не планы.

Разрешения два и они разного уровня: `READ_PLAY_DATA` (dangerous, спрашивает
игрока) для дневника, `EXPORT_PLAY_DATA` (signature, молча) для переноса
между своими версиями. Разные права на разных адресах одного провайдера
сделаны через `path-permission`.

## Про ключ подписи

`android/keystore.jks` (боевой ключ для Google Play) в git не попадал и
попадать не должен — он в `.gitignore`. Лежит только на ноутбуке Алекса.
Его потеря означает невозможность обновлять приложение в Play под тем же
именем. Резервная копия вне ноутбука на момент записки **не сделана**.
