# Deploy: server-side short name generator

**Что и почему**: дефолтное имя игрока в лидерборде было `playerNNN_join_DD.MM.YYYY`
— длинное, не влезает в строку таблицы. Заменено на короткий произносимый
слоговый генератор (`Bran`, `Talish`, `Zanai` и т.п.), реализованный **только
на сервере** — единая логика для нативного приложения и вебапа, ни один клиент
больше не генерирует имя сам, оба просто показывают то, что вернул `sync.php`/
`set_name.php`.

Существующих игроков с уже выбранным вручную именем миграция не трогает —
переименовываются только те, чьё имя до сих пор точно совпадает со старым
автоформатом.

## Изменённые/новые файлы (уже лежат локально в `webapp/api/`)

- `_lib.php` — добавлены `generate_short_name($pdo)` (сам генератор + проверка
  уникальности по живой таблице `players`), `build_name_candidate(...)` (хелпер),
  `looks_like_old_default_name($name)` (детектор старого формата для миграции).
  Старая `default_player_name()` **не удалена** — на неё опирается детектор.
- `sync.php` — оба места, где раньше вызывался `default_player_name(...)`,
  теперь вызывают `generate_short_name($pdo)`.
- `set_name.php` — то же самое: сброс имени на "дефолтное" (`name === null`)
  теперь тоже генерирует слоговое имя, а не `playerNNN_join_...`.
- `.htaccess` — новый `migrate_002_rename_default_names.php` добавлен в список
  запрещённых для прямого HTTP-доступа (как `_lib.php`/`db.php`/`config.php`).
- `migrate_002_rename_default_names.php` (**новый файл**) — одноразовый CLI-
  скрипт миграции существующих игроков.

Всё синтаксически проверено локально (`php -l`, PHP 8.3), генератор
дополнительно прогнан вручную на 15 образцах имён — выглядит нормально.
**Против реальной БД не проверялось** — здесь нет доступа к прод-данным
(`config.php` в этой папке — заглушка без реальных credentials, см.
`webapp/api/README.md`).

## Шаги деплоя

1. **Сделать бэкап** текущих `_lib.php`, `sync.php`, `set_name.php`, `.htaccess`
   с сервера (просто скачать копии через Sprutio) — на случай отката.
2. Залить через Sprutio в `/playoftime.online/public_html/api/`:
   - `_lib.php`
   - `sync.php`
   - `set_name.php`
   - `.htaccess`
   - `migrate_002_rename_default_names.php`
3. **Прогнать миграцию один раз.** Скрипт написан как CLI-only (проверяет
   `php_sapi_name() !== "cli"` и отказывается работать через браузер) — нужен
   доступ к консоли сервера:
   ```
   php migrate_002_rename_default_names.php
   ```
   Выведет построчно `id  старое_имя  ->  новое_имя` и итог
   `Migrated N row(s), left M custom-named row(s) untouched.`

   **Если консоли/SSH нет** (только файловый менеджер Sprutio): временно убрать
   `migrate_002_rename_default_names` из `<FilesMatch>` в `.htaccess`, дёрнуть
   файл один раз через браузер (`https://playoftime.online/api/migrate_002_rename_default_names.php`
   — но тогда убрать и CLI-проверку `php_sapi_name()` в начале файла, иначе он
   откажет с 403), посмотреть вывод, **сразу вернуть** и `.htaccess`, и проверку
   обратно. Предпочтительно первым способом (CLI), если он вообще доступен.
4. **Проверить результат** через phpMyAdmin:
   ```sql
   SELECT id, display_name, updated_at FROM players ORDER BY updated_at DESC LIMIT 30;
   ```
   Должны появиться короткие имена вместо `playerNNN_join_...` у тех, кто не
   задавал имя сам. У игроков с ручными именами `display_name` не должен был
   измениться (сравнить `updated_at` — у нетронутых он не обновится).
5. **Живая проверка**: зайти в приложение (нативное или веб) под свежим/сброшенным
   игроком без сохранённого имени, засинкать — новое имя должно прийти коротким,
   а не `playerNNN_join_...`.

## Откат, если что-то пошло не так

Восстановить с сервера бэкапы `_lib.php`/`sync.php`/`set_name.php`/`.htaccess`
из шага 1. Миграция необратима на уровне "вернуть старые сгенерированные
имена" (они не сохраняются нигде) — но это не критично, это просто дефолтные
имена, не данные игрока.
