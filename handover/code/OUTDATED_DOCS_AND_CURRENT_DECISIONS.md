## 1. `list_of_quests.docx` + `quests_oder.pdf` — система квестов

| Пункт документа | Статус | Актуальное решение (код: `core/utils/Quest.kt`, `MainViewModel.kt`) |
|---|---|---|
| 10 квестов (3 + 3 + 4) | ❌ Устарело | **15 квестов, по 5 на уровень**: L1.1–L1.5, L2.1–L2.5, L3.1–L3.5. L1 получил TWO_IN_N/THREE_IN_N для зеркальности с L2/L3 |
| Квест 3.4: N:=3, шаг N±1 | ❌ Устарело | L3.3/L3.4 поменяны местами (THREE_IN_N → 3.3, TWO_IN_ROW → 3.4), добавлен L3.5 (THREE_IN_ROW — финал игры). Особых N=3-квестов больше нет |
| Адаптация: N и t могут меняться одновременно | ❌ Устарело | **Правило индульгенции: только ОДНА адаптация за раз.** IN_N-квесты → только N±33 (t=0). ROW-квесты → только t±1 мс (окно N=33) |
| Адаптация без потолка | ❌ Устарело | **Капы (3 ступени)**: N ∈ {33, 66, 99}; t ∈ {0, 1, 2, 3 мс} |
| Возврат к baseline: на каждой победе N/t уменьшается на шаг, advance при победе на исходных параметрах | ⚠️ Переработано | **Три правила выхода из субквеста** (`onQuestWindowSuccess`): **Rule 1** — победа уже на baseline → advance. **Rule 2** — победа в субквесте с baseline-качеством (ROW: worst-win-error ≤ базового t; IN_N: финальная победа в первых baseN попытках) → прыжок к baseline + advance. **Rule 3** — обычная победа в субквесте → шаг назад на одну ступень, нужно ещё окно |
| Победа = условие выполнено при текущих параметрах | ⚠️ Уточнено | isWin попытки **замораживается в момент записи** (с допуском на тот момент). Зелёная 2.99 остаётся зелёной после ужесточения. В БД поле `toleranceMs` per attempt (миграция 5→6) |
| — (не описано) | ➕ Новое | Сессия автозакрывается на текущем эффективном N (33/66/99). Worst-win-error для Rule 2 в ROW считается **только по текущему стрику** (сбрасывается на промахе) |

## 3. `measures.docx` + `parametr_table.docx` — метрики и формулы

| Пункт документа | Статус | Актуальное решение |
|---|---|---|
| SCM в секундах | ❌ Устарело | Формула в **миллисекундах** + **level-factor 10^(accuracy−3)**: L1 ×1/100, L2 ×1/10, L3 ×1. Идеальная 3.000: L1 → 0.99 SC, L2 → 9.9, L3 → 99. Файл: `CalculateScmUseCase.kt`. При смене формулы — bump флага рекалькуляции в `LocalStorageService` (сейчас v4) |
| Медиана отклонений | ❌ Устарело | **Геометрическое среднее** (`exp(mean(ln))`), разброс — геометрический CV% |
| Range of Errors = max | ❌ Устарело | **P3/P97 перцентили на знаковых ошибках** (rangeEarlyMs / rangeLateMs). Карточка «RANGE OF DEVIATIONS»: два плоских цвета с резкой границей на `centerFrac = |early|/(|early|+|late|)`; клювик Serenity point НЕПОДВИЖЕН в геометрическом центре (цель игрока — свести стык к клювику) |
| Параметр #14 «All» = |ошибки| | ⚠️ Расщеплено | На аналитике — модульное геом. среднее. На главном экране «Absolute» = **знаковое смещение**: `geomMean(durations) − aim` (< 0 = перекос early). Это сознательное расхождение — индикатор баланса |
| Top Deviations (модусы) по 10мс-бакетам | ❌ Устарело | 1 мс точность; округление **по accuracy самой попытки** (не текущего уровня); нули отбрасываются; модус = count ≥ 2; показываются 2 моды (top red + top blue) внутри карточки Range |
| Lucky Index | ⚠️ Формула уточнена | `empirical / (1/outcomeSlots)` — **больше = лучше** (в ранней реализации была перевёрнута). Слот = ширине окна «чистой тройки» (100/10/1 мс по точности попыток) — вариант A (1 мс везде) ОТКЛОНЁН 2026-07-10: он разрывал пару числитель/знаменатель. Числитель дерева приведён к точности попытки (был мс-точным) |
| Play time = endTime − startTime | ❌ Устарело | **`activeTimeMs`** (Room v7): тикает только пока MainScreen в состоянии RESUMED и сессия открыта. Формат вывода «17.43 h» |
| Excel-экспорт: SCM_i, паузы, session balance | ⚠️ Частично | Экспорт по-прежнему 7 колонок (Date, Time, Session #, Attempt #, Result ms, Error ms, Accuracy). Доработка колонок — открытый бэклог |
